# Сайт усадьбы «Моринское»

Next.js 16 (React 19) со статической сборкой. На выходе — обычные HTML-файлы, которые работают на любом хостинге. Заявки из формы уходят в Telegram через PHP-скрипт `api/send.php`.

## Что где лежит

| Путь | Что там |
|---|---|
| `src/content/site.ts` | Телефон, мессенджеры, адрес, УНП, домен, e-mail, рейтинг, номер счётчика Метрики, заголовок и описание для поисковиков, коды подтверждения Яндекс Вебмастера и Google Search Console |
| `src/content/home.ts` | Все тексты главной: главы, цены, сценарий дня, услуги, вопросы, шаги брони |
| `src/content/slides.ts` | Фото в слайдерах трёх глав и подписи к ним |
| `src/content/gallery.ts` | Галерея «Наши свадьбы»: день, вечер, зима |
| `src/content/map.ts` | Точки на карте усадьбы и фото к ним |
| `src/content/policy.ts` | Текст политики конфиденциальности |
| `src/content/photos.ts` | Подписи к фото для незрячих и точка кадрирования |
| `photos/` | Исходные фото (JPG). Имя файла — ключ фото |
| `public/` | Фавиконы, картинка превью, `.htaccess`, `api/send.php` |
| `src/components/` | Блоки сайта |
| `src/app/globals.css` | Все стили |

## Как поменять текст, цену или фото

1. Текст или цена — поправьте строку в нужном файле из `src/content/`.
2. Новое фото — положите JPG в `photos/` (длинная сторона от 2000 px), затем укажите его имя без `.jpg` в `slides.ts`, `gallery.ts` или `map.ts`, а подпись добавьте в `photos.ts`.
3. Соберите сайт заново (см. ниже) и загрузите папку `out/` на хостинг.

## Сборка

Нужен Node.js 20 или новее.

```bash
npm install
npm run build
```

Команда сама нарежет фото в AVIF и WebP четырёх размеров (`public/img/`) и соберёт сайт в папку `out/`. Браузер сам выбирает лёгкий AVIF, старые браузеры получают WebP. Слайды в главах подгружаются, только когда до них доходит посетитель. Посмотреть локально: `npx serve out`.

## Публикация на hoster.by

1. В панели hoster.by включите для сайта PHP 8.1 или новее и бесплатный SSL-сертификат.
2. Загрузите **содержимое** папки `out/` в корень сайта (обычно `public_html/`) — через файловый менеджер панели или FTP. Скрытый файл `.htaccess` тоже должен попасть на сервер.
3. Настройте Telegram-бота (следующий раздел) и положите файл с настройками.
4. Откройте сайт и отправьте тестовую заявку.

`.htaccess` включает переадресацию на HTTPS и на адрес без `www`, страницу 404, сжатие и кэширование.

## Заявки в Telegram

1. В Telegram откройте @BotFather → `/newbot` → придумайте имя. Бот пришлёт токен вида `123456789:AA...`.
2. Каждый, кто должен получать заявки, находит бота и нажимает «Запустить». Удобнее создать группу, добавить туда бота и всех, кто принимает заявки.
3. Узнайте chat_id: напишите боту (или в группу) любое сообщение и откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates`. Нужно число из `"chat":{"id": ...}`. У групп оно отрицательное.
4. Скопируйте `api/config.sample.php` в файл с настройками и заполните `token` и `chats`:
   - лучше всего — `morinskoe-config.php` **на уровень выше** `public_html`, тогда его нельзя открыть из браузера;
   - если так нельзя — `public_html/api/config.php`, доступ к нему закрыт в `api/.htaccess`.
5. В `origins` оставьте адреса сайта. Если домен другой, замените.

Что делает `send.php`: проверяет имя, телефон и галочку согласия, отсекает ботов (скрытое поле и слишком быструю отправку), ограничивает 5 заявок за 10 минут с одного IP и отправляет сообщение всем чатам из `chats`. Если Telegram не ответил, посетитель видит ошибку с телефоном, а введённые данные остаются в форме.

## Яндекс Метрика

Сейчас Метрика выключена: на сайте нет ни слова об аналитике, а баннера cookie нет, потому что сайт их не ставит. Если понадобится: создайте счётчик на metrika.yandex.ru (Вебвизор не включайте), впишите номер в `metrikaId` в `src/content/site.ts` и пересоберите сайт. Тогда сами появятся баннер cookie, ссылка «Настройки cookie» внизу сайта и пункты про аналитику в политике конфиденциальности, а Метрика будет загружаться только после согласия посетителя.

## Отзывы с Яндекс Карт

Блок «Отзывы» показывает рейтинг с Яндекс Карт и кнопку «Оставить отзыв». Виджета Яндекса на сайте нет, поэтому рейтинг и число оценок обновляются вручную: `rating.value`, `rating.stars` и `rating.count` в `src/content/site.ts`.

## Поисковики

Что уже есть на сайте:

- заголовок и описание страницы — `title` и `description` в `src/content/site.ts`, они же уходят в превью ссылок в Telegram, Viber и соцсетях;
- разметка schema.org: усадьба как площадка для мероприятий и место для ночлега (адрес, телефон, координаты, фото, вместимость, цены на меню), вопросы и ответы из блока «Вопросы пар», хлебные крошки у политики;
- `sitemap.xml` со всеми фотографиями главной — так они быстрее попадают в поиск по картинкам;
- `robots.txt`, канонические адреса, переадресация с `/index.html`, `noindex` для страницы 404 и для демо.

Что сделать один раз после запуска:

1. **Яндекс Вебмастер** (webmaster.yandex.ru): добавьте сайт, выберите подтверждение через мета-тег и впишите код из `content="…"` в `yandexVerification` в `src/content/site.ts`. Пересоберите и выложите сайт, нажмите «Проверить». Затем: «Индексирование → Файлы Sitemap» — добавьте `https://домен/sitemap.xml`; «Информация о сайте → Региональность» — укажите Гродненскую область.
2. **Google Search Console** (search.google.com/search-console): ресурс «Префикс URL», подтверждение через тег HTML, код — в `googleVerification`. После подтверждения добавьте sitemap.
3. **Яндекс Бизнес**: в карточке организации укажите адрес сайта. Карточка и сайт усиливают друг друга в выдаче и на картах.
4. **Google Бизнес-профиль** (business.google.com): создайте карточку с тем же адресом, телефоном и сайтом, что и на сайте.
5. Проверьте разметку: search.google.com/test/rich-results и webmaster.yandex.ru/tools/microtest.

Рейтинг с Яндекс Карт в разметку не выводится: Google запрещает переносить в неё оценки с других сайтов.

## Демо на Firebase

Для показа можно выложить сайт на Firebase Hosting. PHP там не работает, поэтому для демо есть отдельная сборка: форма имитирует отправку и показывает «Это демо: заявка никуда не отправлена», внизу страницы стоит пометка «Демо-версия», а поисковикам запрещено индексировать страницы.

1. Установите Firebase CLI и войдите: `npm install -g firebase-tools`, затем `firebase login`.
2. В консоли Firebase создайте проект. В `.firebaserc` замените `morinskoe` на ID проекта.
3. Соберите демо: `npm run build:demo`. Готовые файлы появятся в `out-demo/`.
4. Выложите: `firebase deploy --only hosting`. Сайт откроется по адресу `https://ID-проекта.web.app`.

Настройки хостинга лежат в `firebase.json`: страница 404, адреса со слешем на конце, кэширование и заголовок `noindex`.

## GitHub и автопубликация

Проект готов к работе через GitHub: история правок и публикация без ручной загрузки файлов.

1. Создайте на GitHub пустой **приватный** репозиторий без README, например `morinskoe-site`.
2. В папке проекта выполните:
   ```bash
   git remote add origin https://github.com/ЛОГИН/morinskoe-site.git
   git push -u origin main
   ```
3. **Демо на Firebase** публикуется само при каждом пуше в `main`. Нужно один раз добавить в GitHub → Settings → Secrets and variables → Actions:
   - секрет `FIREBASE_SERVICE_ACCOUNT` — JSON-ключ из Firebase Console → Project settings → Service accounts → Generate new private key;
   - переменную `FIREBASE_PROJECT_ID` — ID проекта Firebase.

   Пока секрета нет, сборка демо просто пропускается.
4. **Боевой сайт на hoster.by** выкладывается по кнопке: Actions → «Публикация на hoster.by» → Run workflow. Нужны секреты `FTP_SERVER`, `FTP_USERNAME`, `FTP_PASSWORD` (данные FTP из панели hoster.by). Если сайт лежит не в `public_html/`, добавьте переменную `FTP_DIR`. Файл настроек бота `api/config.php` на сервере не перезаписывается.

Токен бота, пароль FTP и ключ Firebase храните только в секретах GitHub и на сервере — в репозиторий их не добавляйте. `api/config.php` уже исключён в `.gitignore`.

## Другой домен

Поменяйте `url` в `src/content/site.ts` и `origins` в файле настроек бота, затем пересоберите сайт. Домен подставится в метатеги, превью ссылки, sitemap, robots.txt и политику.

## Что проверить после запуска

- Сайт открывается по `https://`, адрес с `www` перенаправляет на основной.
- Тестовая заявка приходит в Telegram.
- Несуществующий адрес показывает страницу 404, а через 6 секунд сам открывает главную. Кнопка «Остаться здесь» отменяет переход.
- Превью ссылки в Telegram: если показывается старое, обновите через @WebpageBot.
- Сайт подключён к Яндекс Вебмастеру и Google Search Console (см. «Поисковики»).
- Впишите e-mail для обращений в `email` в `src/content/site.ts` — он появится в политике конфиденциальности.

## Если заявки упираются в лимит

Лимит считается по IP посетителя. Если хостинг стоит за прокси и `send.php` видит один и тот же адрес у всех, лимит сработает на весь сайт. Проверьте, какой IP приходит в `REMOTE_ADDR`, и при необходимости укажите в файле настроек `'ip_header' => 'HTTP_X_REAL_IP'` (или заголовок, который передаёт хостинг).
